# ADR-001：规则 DSL 采用「IR → 确定性编译 → 版本化 DSL」两阶段

- 状态：已接受（设计层面）
- 日期：2026-10-24
- 影响范围：`packages/rule-schema`、`apps/api/app/compiler`（未实现）、客户端 `RuleRuntime`（未实现）

## 背景

玩家用自然语言描述规则，服务端 LLM 负责把这句话变成机器可执行的东西。
如果直接把模型输出当代码或当 JSON 直接执行，会遇到三类不可控风险：

1. **安全**：模型可能产出任意表达式、动态属性访问、无限循环。
2. **可复现**：同一句话每次生成不同结构，挑战链接无法冻结。
3. **可验证**：失败时无法定位是「模型说错了」还是「引擎执行错了」。

## 决策

采用两阶段格式：

1. **阶段一：Rule IR** — 模型只允许输出受控 IR：选择预先注册的 Trigger / Condition / Operation 并填写受限参数。未知 op、超范围参数一律拒绝。
2. **阶段二：DSL** — 确定性编译器把 IR 补全为带版本号的完整 DSL 文档（`dslVersion` = `1.1.0`），执行 schema、类型、语义、冲突与关卡兼容性五层校验，通过后才返回 `ready`。

执行侧只在浏览器本地运行 DSL，**不存在**「服务端执行玩家规则」这条路径。

## 后果

**正面**
- 模型无法注入可执行代码；攻击面收敛到「已注册 op + 参数范围」。
- 编译是确定性的：同一 IR 得到同一 DSL，可哈希、可缓存、可冻结进挑战链接。
- 校验失败与执行失败在日志里天然可区分。

**代价**
- 表达力受限于注册表（P0 只开放 12 个动作），复杂规则需要扩表。
- 需要维护 `packages/rule-schema` 作为前后端单一真相源，并通过契约测试同步 Python 与 TypeScript。

## 被否决的方案

- **直接执行模型返回的 JS**：不可验证、不可复现，安全上不可接受。
- **只依赖 DeepSeek JSON mode**：它只保证 JSON 语法合法，不保证字段、枚举、参数范围或关卡兼容性，因此仍需完整校验链路。
