## 怎么跑

```bash
cd apps/api

# 离线：验证评测框架本身（CI 用，不花配额）
uv run python eval/run_eval.py --provider mock

# 真实模型：产生本文数据（花费真实配额，约 30 分钟）
uv run python eval/run_eval.py --provider deepseek
```

语料 300 条，分布：简单 60 / 组合 90 / 条件 60 / 拒绝 60 / 双语 30。

## 剩余 2 条失败

| ID | Prompt | 结果 | 性质 |
|---|---|---|---|
| k36 | 当玩家血量大于 3 时，获得护盾 | `finish_reason=length` 重试后仍截断（39s） | **基础设施**，非语义错误 |

## 语料从 50 → 300 的演进

### 第一轮（50 条）：77.5%

逐条核对后发现**责任分属三方**，这个区分比修 bug 本身更重要：

| 问题 | 责任方 | 处理 |
|---|---|---|
| 模型用 `scale` / `multiplier` 当参数名 | 提示词缺陷 | 补上每个动作的精确参数名与范围 |
| `checkpoint.activate` / `platform.visibility.set` 被拒 | 编译器缺陷 | 按关卡能力补合法默认 id |
| `timer.interval` 从不触发 | 运行时缺陷 | 实现定时事件（≥500ms） |
| 未知参数被静默忽略（要 100 倍得到 1.2 倍） | 校验缺陷 | 未知参数直接拒绝 |
| "多个动作应生成多条规则" | **我的测试期望错误** | 规范允许 1 条规则 2 个动作，下限改为 ceil(动作数/2) |

### 第二轮（300 条）：94.6%

又暴露两个问题：

| 问题 | 责任方 | 处理 |
|---|---|---|
| 6 条 `激活检查点` 全部被拒 | 提示词缺陷 | 明确告知模型：关卡 id 可以省略，服务器会补 |
| 4 条双语变体是病句（「当金币会逃跑时」） | **我的生成器 bug** | 改为 30 条人工撰写的自然句子 |

**又一次：部分失败是我自己的测试数据造错了。** 如果当时直接去改产品，
会把本来正确的行为改坏。

### 第三轮（300 条）：99.2%

剩余 2 条如上，一条基础设施、一条模型漏判。

## 置信区间怎么读

300 条样本下 99.2% 的 95% 置信区间是 **[97.0%, 99.8%]**。

含义：真实能力**很可能**在这个区间内，但**不能说"稳定 99.2%"**。
若要把区间收到 ±1%，需要约 1000 条样本。

## 已知局限

1. **语料是生成的，不是真实用户日志**。它覆盖了语法形态，但真实玩家会写出
   更口语、更含糊、更长的句子。
2 . **单一模型**：只测了 deepseek-flash。切模型后必须重跑。
3. **单次采样**：每条 Prompt 只调用一次。temperature=0.2，所以同一条重跑可能
   有不同的 `status`。要测稳定性需要对同一批跑 3 次。
4. **中文为主**：双语覆盖 30 条，英文单语场景未单独评测。

## 复现

报告含 `corpusVersion` / `provider` / `model` / 每条用例的 `latencyMs` 与
`compiledStatus`。换模型重跑只需 `--provider`。
`tests/test_eval_harness.py` 会断言 `prompts.json` 与生成脚本一致，
防止手改导致计数漂移。
