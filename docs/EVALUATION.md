## 怎么跑

```bash
cd apps/api

# 真实模型：产生本文数据（花费真实配额，约 30 分钟）
uv run python eval/run_eval.py --provider deepseek
```

## 语料从 50 → 300 的演进

### 第一轮（50 条）：77.5%

逐条核对后发现**责任分属三方**，这个区分比修 bug 本身更重要：

| 问题 | 责任方 | 处理 |
|---|---|---|
| 模型用 `scale` / `multiplier` 当参数名 | 提示词缺陷 | 补上每个动作的精确参数名与范围 |
| `checkpoint.activate` / `platform.visibility.set` 被拒 | 编译器缺陷 | 按关卡能力补合法默认 id |
| `timer.interval` 从不触发 | 运行时缺陷 | 实现定时事件（≥500ms） |
| 未知参数被静默忽略（要 100 倍得到 1.2 倍） | 校验缺陷 | 未知参数直接拒绝 |
| "多个动作应生成多条规则" | **我的测试期望错误** | 规范允许 1 条规则 2 个动作，下限改为 ceil(动作数/2) |

### 第二轮（300 条）：94.6%

又暴露两个问题：

| 问题 | 责任方 | 处理 |
|---|---|---|
| 6 条 `激活检查点` 全部被拒 | 提示词缺陷 | 明确告知模型：关卡 id 可以省略，服务器会补 |
| 4 条双语变体是病句（「当金币会逃跑时」） | **我的生成器 bug** | 改为 30 条人工撰写的自然句子 |

**又一次：部分失败是我自己的测试数据造错了。** 如果当时直接去改产品，
会把本来正确的行为改坏。

### 第三轮（300 条）：99.2%

剩余 2 条如上，一条基础设施、一条模型漏判。


## 稳定性测量（同一批 Prompt 跑多次）

单次评测只能回答"能不能过"，回答不了"稳不稳"。为此运行器支持
`--repeats` 与分层 `--sample`：

```bash
# 3 轮 × 分层抽样 60 条 = 180 次真实调用
uv run python eval/run_eval.py --provider deepseek --repeats 3 --sample 60
```

### 结果：判定完全稳定

| 指标 | 结果 |
|---|---|
| 每轮通过率 | **[1.0, 1.0, 1.0]** |
| 轮间极差 | **0.00%** |
| 每轮都通过 | 60 |
| 从未通过 | 0 |
| 时好时坏 | **0** |
| 判定翻转率 | **0.00%** |

180 次调用里**没有任何一条 Prompt 的判定发生过变化**。

### 但那次全量评测里的 2 条"失败"是噪声

全量 300 条里有 2 条失败（k36 截断、b28 unsupported）。针对这两条各重测 8 次：

| Prompt | 8 次结果 | 结论 |
|---|---|---|
| k36 当玩家血量大于 3 时，获得护盾 | ready × 8 | **偶发截断**，非稳定缺陷 |
| b28 落地时重力反转 | ready × 8 | **偶发漏判**，非稳定缺陷 |

k36 在稳定性抽样的 60 条里也是 3/3 通过，进一步佐证。

**这意味着 99.2% 这个数字本身含有噪声**：它是单次采样，重跑可能变成 99.6% 或 98.8%。
真实的"稳定通过率"更接近 **99.5% ± 0.5%**。

### 真正不稳定的地方：延迟

| 场景 | 中位数 | P95 | 最大 |
|---|---|---|---|
| 全量 300 条（单次） | 4.0 s | **10.3 s** | — |
| 抽样 60 条（第 3 轮） | 6.3 s | **14.6 s** | 19.8 s |
| k36 定向 8 次 | 11.0 s | — | **40.7 s** |

**判定稳，延迟不稳。** P95 在 10–15 秒之间摆动，正好压在 15 秒目标线附近。
k36 单次最慢 40.7 秒，来源是输出被截断后重试一次——这会把单次耗时直接翻倍。

所以"P95 达标"这个结论**并不稳固**：它取决于这次跑的网络状况。

### 结论怎么读

1. **能力判定的稳定性可以确认**：同样的输入，模型给出的规则结构是稳定的。
2. **延迟不能保证**：15 秒的目标在好网络下达标，在差网络下会超。
3. **单次评测的数字有 ±0.5% 左右的噪声**，写进报告时应说明这一点。

## 置信区间怎么读

300 条样本下 99.2% 的 95% 置信区间是 **[97.0%, 99.8%]**。

含义：真实能力**很可能**在这个区间内，但**不能说"稳定 99.2%"**。
若要把区间收到 ±1%，需要约 1000 条样本。

## 已知局限

1. **语料是生成的，不是真实用户日志**。它覆盖了语法形态，但真实玩家会写出
   更口语、更含糊、更长的句子。
2 . **单一模型**：只测了 deepseek-flash。切模型后必须重跑。
3. **单次采样带来的噪声**：已测（见上文稳定性一节）。判定稳定，但单次数值有
   ±0.5% 左右波动；延迟波动更大。
4. **中文为主**：双语覆盖 30 条，英文单语场景未单独评测。

## 复现
