# 关卡设计：lab-01 天空遗迹

> 状态：**设计文档。关卡数据与运行时属于 RF-003，尚未实现。**
> 依据 `images/05-level-environments.png`（主题 01）与 `images/04-gameplay-ui-rulecards.png`（HUD / 规则卡片）。
> 设计只使用 DSL v1.1 已注册的 8 个事件与 12 个动作，不发明新 API。

## 1. 教学节奏

一关只教一件事。lab-01 的教学目标是：**玩家第一次亲手改写世界规则，并立刻看到后果。**

| 段落 | 时长 | 教什么 | 规则状态 |
|---|---|---|---|
| A 起步 | 0–15s | 移动、跳跃、吃金币 | 无规则 |
| B 解锁 | 15–30s | 拿到第一张规则卡，输入框点亮 | 可输入 1 条 |
| C 实验 | 30–60s | 规则生效，世界真的变了 | 1 条生效 |
| D 收束 | 60–90s | 用规则解决问题，抵达传送门 | 最多 3 条 |

## 2. 场景布局（横向 1 屏半，摄像机跟随）

```text
起点平台(教学)      云朵浮台群        断桥(需跳跃)       金币廊道        传送门平台
   ▓▓▓▓          ▓▓   ▓▓▓▓           ▓▓           ▓ ▓ ▓ ▓        ▓▓▓▓▓▓▓
   ↑出生点        ↑首个跳跃点       ↑需要规则帮助    ↑风险区        ↑终点
```

- **断桥段是规则的教学钩子**：缺口 320px，正常跳跃跨不过去。
  玩家拿到「平台消失」或「二段跳」类规则后才能通过 —— 这是"规则真的有用"的第一个证据。
- 背景三层视差：远山浮岛（慢）→ 瀑布与云（中）→ 前景云片（快）。
- 存档信标放在 C 段入口，死亡不回到起点。

## 3. 关卡目标（对应 HUD 右侧面板）

| 目标 | 初始值 | 类型 |
|---|---|---|
| 收集金币 | 0 / 20 | 可选 |
| 抵达传送门 | 0 / 1 | 必需 |
| 找回规则碎片 | 0 / 3 | 必需（解锁输入框） |

只有「抵达传送门」是通关条件；另外两个驱动探索。这条规则要写进关卡数据，
不要写死在场景脚本里。

## 4. 与 DSL 的绑定（只列已注册项）

| 关卡元素 | 事件 | 动作 |
|---|---|---|
| 可坍塌浮台 | `player.landed` | `platform.collapseAfter`（delayMs 250–5000） |
| 金币 | `coin.collected` | `coin.spawn` / `coin.flee` |
| 教学敌人：机械蟹兵 | `player.enterZone` → 巡逻 | `enemy.speed.multiply` |
| 教学敌人：泡泡无人机 | `timer.interval`（≥500ms） | `enemy.spawn`（1–2/次） |
| 重力反转区（C 段） | `player.jumpCommitted` | `player.gravity.toggle`（magnitude 500–1400） |
| 终点传送门 | `player.enterZone` | `checkpoint.activate` |

资源上限约束（设计期就要守住）：
一包 ≤ 3 条规则，每条 ≤ 3 条件节点 / ≤ 2 动作，持续时间 ≤ 10s，周期触发 ≥ 500ms。

## 5. 三条预设规则（无需密钥即可玩）

与 `game-content/presets/` 对应，卡片文案直接用自然语言：

1. **每跳一次，重力反转** — `player.jumpCommitted` → `player.gravity.toggle`
2. **踩上去两秒后，浮台消失** — `player.landed` → `platform.collapseAfter(2000)`
3. **金币会逃跑** — `player.enterZone` → `coin.flee(radius 120, speed 80)`

## 6. 视觉规格（取自 ART_DIRECTION）

- 场景底色 `#00162B`，远景发光 `#79B4E6`，可交互边缘统一 `#61CDF4`。
- 敌人一律比主角暗一档，避免干扰视线；可交互物件必须带青色描边，这是玩家的唯一提示。
- 平台顶面用纯白高光（`#F2F4F9`），让「可以站」一眼可读。
- 危险物（尖刺 / 岩浆）只用珊瑚粉 `#E99BA6` 到深红的渐变，绝不与青色混用。

## 7. 验收标准（RF-003 完成时逐条验证）

- [ ] 键鼠与触屏都能完成 A→D 全程
- [ ] 死亡 0.8s 内复活，且回到最近信标而非起点
- [ ] 三条预设规则逐条生效，关闭后效果完全消失（无残留状态）
- [ ] 规则生效时最长 10s 内自动清理，不泄漏定时器
- [ ] 60fps（1080p / 中端核显）
- [ ] 画布在 960×540 逻辑分辨率下等比适配，移动端不裁切 HUD
